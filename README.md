# Apryse iOS PTStamper large-document repro

Minimal React Native reproduction for Apryse support ticket `#207263`. It
demonstrates the fail-closed delay and lock contention produced by applying a
tiled image watermark to every page of a large PDF with `PTStamper`.

The project contains no application source, credentials, license keys, or
customer documents. Test PDFs are generated locally from synthetic content.

## Versions

- React Native `0.83.4`
- `@pdftron/react-native-pdf` `3.0.4-29`
- PDFNet iOS `12.1.0.30566`
- `patch-package` `8.0.1`

## What the repro does

1. Serves a synthetic, linearized PDF over HTTP with byte-range support.
2. Allocates a fresh native Apryse document-cache directory, then opens a
   cache-busted remote URL in `DocumentView`.
3. Builds a synthetic text tile and repeats it into a full-page, Retina-scale
   PNG composite, matching the expensive tiled-image architecture.
4. Requests stamping from Apryse's streaming callback, acquires `DocLock:NO`,
   and calls `PTStamper StampImage` over a `PTPageSet` containing every page.
5. Logs write-lock wait, composite/`StampImage`, and total native durations.
6. Keeps the native viewer fully transparent until native code confirms that
   stamping succeeded. Errors remain fail-closed.

There is intentionally no post-download control mode. This project reproduces
the unsupported overlap required by the product: stream, mutate every page, and
remain fail-closed. The patch mutates only the in-memory `PTPDFDoc`; it never
saves the watermarked PDF.

## Observed cold-cache results

Representative iOS Simulator runs with the default local network profile:

- 6,154 pages: about 3.75 s downloading plus 1.39 s stamping (about 5.1 s
  fail-closed); one run waited about 762 ms for the write lock.
- 11,717 pages: about 7.7 s downloading plus 1.19 s stamping (about 8.9 s
  fail-closed).

These are best-case local-server measurements, not production-network
benchmarks. The significant result is the phase ordering: although stamping is
requested from the streaming callback, the observed native event sequence does
not provide a usable first-page window in which a page can be safely displayed.
Fail-closed display therefore waits for both download activity and whole-document
mutation. Warm SDK-cache runs are intentionally avoided because they hide that
constraint.

## Setup

Install prerequisites:

```sh
brew install qpdf
npm install
npm run generate:pdfs
bundle install
bundle exec pod install --project-directory=ios
```

`qpdf` linearizes the generated documents. The generator still creates valid
PDFs without it, but they will not exercise Apryse's linearized streaming path.

Start the range server in one terminal:

```sh
npm run serve:pdfs
```

By default the server adds 12 ms request latency and caps each response at
8 MB/s. Override either value when comparing network profiles:

```sh
LATENCY_MS=40 BANDWIDTH_KBPS=2048 npm run serve:pdfs
```

Start Metro and the iOS app in separate terminals:

```sh
npm start
npm run ios
```

The default server URL, `http://127.0.0.1:8080`, works in the iOS Simulator.
For a physical device, enter the Mac's LAN URL in the app, for example
`http://192.168.1.20:8080`. Both devices must be on the same network.

No Apryse key is included. The app initializes with an empty key for evaluation
mode. If Apryse requires a licensed run, supply a key locally without committing
it.

## Test cases

- `synthetic-6154-pages.pdf`: approximately 20 MB and 6,154 pages
- `synthetic-11717-pages.pdf`: approximately 52 MB and 11,717 pages

Watch both Metro and Xcode logs. Native measurements use the prefix
`[PTStamperRepro]`; range requests are printed by the local server.

Expected success output resembles:

```text
[PTStamperRepro] stamp requested
[PTStamperRepro] write lock acquired waitMs=... pages=6154
[PTStamperRepro] StampImage complete stampMs=...
[PTStamperRepro] result success=1 pages=6154 lockWaitMs=... stampMs=... totalMs=...
```

Record physical-device model, iOS version, document, elapsed times, thermal
state, and whether scrolling or closing the viewer becomes unresponsive.

## Patch

`patches/@pdftron+react-native-pdf+3.0.4-29.patch` is generated by
`patch-package` and reapplied by `postinstall`. It only adds the narrow iOS
watermark repro API, timing events, and matching JavaScript prop declarations.
